# 表情、群记忆与连续消息排查（2026-10-29）

基线：`ffc8b59`。证据来自生产`qbot.log`及3份轮转日志，2026-10-22至2026-10-28，共105404条事件。原始聊天及真实图片不提交Git。

## 结论与修复

| 问题 | 证据/根因 | 处理 |
| --- | --- | --- |
| 标签可能与实际表情不符 | 原工具仅提供top3名称、标签与路径，主模型没有像素输入 | 同一主模型下一次请求接收真实候选图片；静态最大512px，动图首/中/末帧。仅成功预览的路径可提交，禁止同批先检索后直接发送 |
| 表情带引用 | 321次成功投递中106次带表情，其中76次附引用；发送器给各段重复加reply | 表情段和表情失败后的文字兜底均直接发送；文字的明确引用可以保留 |
| 普通回答频繁引用 | 默认agent路径无条件设置`lease.reply_to=当前消息ID`；321次成功投递中196次带引用 | 默认普通发送，必要时使用`quote_message`选本轮具体消息；兼容模式强调reply控制工具与QQ引用不同 |
| 群记忆疑似未运行 | 301次整理请求、300次提交，文件中已有习惯和词典；单行是JSON紧凑格式。默认实际为24条或180秒 | 改为20条或180秒，JSON美化；修复单条尾消息永不处理、全部候选被拒仍确认pending完成。拒绝原因只记录类别/数量 |
| 群记忆丢失机会 | 62批候选全部被拒仍标记完成，共涉及215条pending；原窗口中部分消息仍可能作为后续证据 | 全拒时纠正一次，再次全拒保留pending并按原逻辑退避。合法空结果可正常完成；不降低证据门槛 |
| 历史摘要疑似未运行 | 实际12次成功压缩（两个群8次、私聊4次）；配置20指已投递轮数，非20条入站消息。摘要仅在内存，重启丢失 | 保留增量压缩，已投递历史和摘要原子保存至`data/conversations`并启动恢复，最多500会话/7天/每文件2MiB；/reset同时清理。首次启用不能恢复此前已丢失内存 |
| 连续说明被打断 | trace `8c1b3bb8321a47f5b03769ffb0112639`在选表情期间收到同作者补充，却继续发送旧答案；原因是任意业务工具都会禁用新输入复核 | 业务工具不再绕过发送前检查；两种模式按作者合批；保留完整批次避免32条被8条缓存截掉；正确识别引用自己消息的补充，等待任务不再取消队列owner |
| 表情显示太大 | 仅以普通image发送原始字节 | NapCat的image设置`sub_type=1`与`summary`；发送最大边320px/最大2MiB派生副本，保留动画/透明。原图、索引hash和embedding不变；派生缓存有界 |
| 普通图片误入库 | 日志将仅45×28像素的“43 ms”数值截图判为无奈反应图；prompt直接列“低清网图、截图配字”，程序仅验类型及标签 | 明确可复用反应、对具体内容依赖及可见依据，程序要求一致的结构化判定。低清/动漫/截图/配字不单独授权采集；附加问答不授权采集。旧描述不能授权新增，已有图片不自动删除 |

群聊观察记忆仍要求习惯至少3条同作者证据、词典至少2条；后台记忆整理与已投递对话摘要是不同功能。

## 验证

新增离线检查：`sticker_vision_check.py`、`reply_delivery_check.py`、`history_persistence_check.py`、`sticker_media_check.py`，并扩展分类、群记忆与时序检查。复现先失败，再验证修复。既有发送断言更新为检查表情子类型、尺寸及原图不变；作者来源检查更新为现行“只操作当前用户”约束。Windows上需用`PYTHONUTF8=1`运行旧测试的默认编码读写。

独立审查补充修复两处回归：付费生图不可重放，已经发起时保留结果避免重复执行；兼容模式将其他作者的只读背景与当前作者可消费片段分开。两项均新增先失败后通过的生产调用链检查。

最终本地27个离线模块通过（其中354项unittest，1项平台条件跳过；其余为脚本断言）。Linux隔离副本的全套首轮27/27；收尾复测有4项在主机负载升高时超时，低优先级串行重测全部通过。最后一次主模型看图/引用抽查4/4、补充/对象抽查2/2；独立复核确认原两项P2关闭。

真实API检查均在服务器权限0700的临时副本进行，QQ发送模拟，凭据副本由EXIT清理：

- `live_sticker_vision_check.py --repeats 2`：8/8。真实RAG图片、故意错误的标签配普通状态截图、普通直接回答、显式引用，各两轮。主模型收到像素后能拒绝误导标签。
- `live_sticker_classification_check.py --repeats 2`：6/6。45×28数值截图拒收，夸张反应和点赞图允许入库，各两轮。旧prompt本次对照也判对数值图，因此历史误收是概率性语义错误，不声称每次必现。
- `live_turn_timing_check.py --case inflight_followup --case multi_author_batch --case wait_then_followup --repeats 2`：6/6。验证真实OneBot入站、模型请求和模拟投递。

模型看图与采集判定仍可能出错；结构校验和发送前再看图是两道独立检查，不能保证语义零误判。动图仅预览抽样帧。部署不自动删除既有误收文件。
